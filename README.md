# koshi

単一バイナリのターミナルマルチプレクサ。

名前は格子（こうし）に由来する。

## 特徴

- AIエージェントの管理機能などは無く、純粋にターミナルマルチプレクサとしての使いやすさを追求
- サーバーとクライアントを軽量な 1 つのバイナリで提供する。追加のランタイムを要求しない
- サーバーが疑似端末と画面の状態を持ち、クライアントは入力の送信と描画だけを行う
- デタッチしてもペインのプロセスは動き続け、繋ぎ直すと画面が復元される
- マウス操作への最適化
- ペイン、タブ、名前付きワークスペースを持つ
- 通信は Unix ドメインソケットのみ。TCP を開かず、外部へも接続しない

## インストール

```sh
cargo install koshi
```

## 使い方

```sh
koshi                 # 起動してアタッチする。サーバーが無ければ起動する
koshi kill            # サーバーを止める（状態を保存して終了）
koshi server          # 前面でサーバーを動かす
koshi server --daemon # 端末から切り離してサーバーを動かす
koshi --version
```

アタッチ中のクライアントを終了しても、サーバーとペインのプロセスは動き続ける。
もう一度 `koshi` を実行すると同じ画面に戻る。

ペインで動くシェルには `KOSHI_PANE` が入る。起動ファイルから自動でアタッチするときは、
これを見て二重起動を避ける。

```zsh
if [[ -o interactive && -z $KOSHI_PANE ]]; then
  exec koshi
fi
```

## 操作

### 状態

leader の直後の 1 キーをコマンドとして解釈する。`SCROLL` だけはキーを押しても留まる。

| 状態 | 入り方 | キー | 抜け方 |
| --- | --- | --- | --- |
| `NORMAL` | 起動直後、コマンドの実行後 | そのままペインへ送る | — |
| `PANE` / `TAB` / `SESSION` | `Ctrl+p` / `Ctrl+t` / `Ctrl+o` | 次に押した 1 キーだけを実行 | 実行後。`Esc`、同じ leader、割り当てのないキーでも戻る |
| `SCROLL` | `Ctrl+s` | 次に押した 1 キーを実行し、そのまま留まる | `Esc`、同じ leader、割り当てのないキー |
| ワークスペース一覧 | `Ctrl+o w` | 移動、切替、作成、改名、削除 | `Enter` で切替、`q` か `Esc` で閉じる |

### leader を使わない操作

`Alt` + 矢印は leader を押さずに利用できる。

| キー | 動作 |
| --- | --- |
| `Alt`+`←` / `↑` / `↓` / `→` | その方向のペインへフォーカス。ペインが無いときは `←` / `→` が前 / 次のタブ（折り返し） |

### leader を使う操作

ステータスバーの左端が `[NORMAL]` / `[PANE]` / `[TAB]` / `[SESSION]` / `[SCROLL]`
になり、leader 待ちのあいだはそのグループで使えるキーのヒントが並ぶ。

| leader | グループ |
| --- | --- |
| `Ctrl+p` | ペイン |
| `Ctrl+t` | タブ |
| `Ctrl+o` | セッション |
| `Ctrl+s` | スクロール |

| グループ | キー | 動作 |
| --- | --- | --- |
| ペイン | `←` / `↑` / `↓` / `→` | 左 / 上 / 下 / 右のペインへフォーカス |
| ペイン | `p` | 次のペインへフォーカス |
| ペイン | `;` | 直前にフォーカスしていたペインへ戻る |
| ペイン | `n` / `r` | 右に分割 |
| ペイン | `d` | 下に分割 |
| ペイン | `x` | ペインを閉じる |
| ペイン | `z` | 全画面化の切り替え |
| ペイン | `f` | フローティングペインの表示切り替え |
| タブ | `n` | タブ作成 |
| タブ | `x` | タブを閉じる（最後の 1 枚は残る） |
| タブ | `r` | タブ名の変更 |
| タブ | `←` / `→` | 前のタブ、次のタブ |
| タブ | `1`〜`9` | その番号のタブへ |
| タブ | `Tab` | 直前に見ていたタブへ |
| セッション | `w` | ワークスペース管理画面 |
| セッション | `r` | 現在のワークスペース名の変更 |
| セッション | `d` | デタッチ |
| スクロール | `↑` / `↓` / `k` / `j` | 1 行上 / 下 |
| スクロール | `Ctrl+f` / `Ctrl+b` | 1 ページ下 / 上 |
| スクロール | `d` / `u` | 半ページ下 / 上 |
| スクロール | `Ctrl+c` | 末尾へ戻る |

フローティングペインはタブに 1 枚だけ出せる。表示中はキー入力がそのペインへ送られ、
`Ctrl+p` では `f`（隠す）、`x`（閉じる）、`d`（デタッチ）だけが効く。`Esc` でも隠れるが、
中のプログラムが alternate screen を使っているあいだは、そのプログラムへ渡る。

### マウス

クリックで入力先を選び、ホイールで履歴を読む。アプリがマウス報告を有効にしている
あいだは、ホイールと中・右ボタンをアプリへ送る。alternate screen ではホイールを
`↑` / `↓` に変えて送る。

左ボタンのドラッグは常に koshi 側の選択動作になり、離すと OSC 52 でクリップボードへ入る。
動かさずに離したクリックだけは、報告中のアプリへ press と release を送る。
コピーすると右下に `copied N chars` が 2 秒出る。

ペインの境目は左ボタンで掴んで動かせる。どちらのペインも 1 桁（1 行）を下回らない。
ワークスペース一覧の行もマウスで選べる。

## 設定

`$XDG_CONFIG_HOME/koshi/config.toml`（無ければ `~/.config/koshi/config.toml`）。
ファイルが無ければ既定値で起動し、壊れていれば既定値で起動してその旨を標準エラーへ出す。

```toml
leader = "C"        # "C" は Ctrl+p/t/o/s、"A" は Alt+p/t/o/s
scroll_lines = 3    # ホイール 1 ノッチの行数
history_lines = 10000
```

## 状態ファイル

- 置き場所は `$XDG_STATE_HOME/koshi/state.bin`（無ければ `~/.local/state/koshi/state.bin`）。
  `KOSHI_STATE_DIR` か `KOSHI_RUNTIME_DIR` を指定すると、そのディレクトリに置く
- ディレクトリは 0700、ファイルは 0600。3 秒ごと（変更があったときだけ）と終了時に、
  一時ファイルからの `rename` で置き換える
- 残るのはワークスペースとタブの並び、レイアウト、フォーカス、ペインの作業ディレクトリ、
  履歴のテキスト。履歴は 1 ペイン 2000 行、全体で 400 KB まで
- 復元すると各ペインは同じディレクトリで新しいシェルを開く。実行中だったプロセスは戻らない。
  フローティングペインは保存しない
- 壊れている、形式が違う、チェックサムが合わないときは空の状態で起動し、最初のクライアントへ
  1 行知らせる。形式バージョンは 1

## コピー

コピーは OSC 52 を使う。端末が受け付ける上限は端末ごとに違い、koshi からは
分からないので、切り詰めも分割もしない。

`git log` の既定の pager（`less -FRX`）は alternate screen を使わない。この場合は
ホイールが koshi の履歴を動かすので、ログ全体を読みたいときは `LESS=` を空にするか
`core.pager = less -R` を設定する。
