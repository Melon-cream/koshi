# koshi

単一バイナリのターミナルマルチプレクサ。

名前は格子（こうし）に由来する。

## 特徴

- AIエージェントの管理機能などは無く、純粋にターミナルマルチプレクサとしての使いやすさを追求
- サーバーとクライアントを軽量な 1 つのバイナリで提供する。追加のランタイムを要求しない
- サーバーが疑似端末と画面の状態を持ち、クライアントは入力の送信と描画だけを行う
- デタッチしてもペインのプロセスは動き続け、繋ぎ直すと画面が復元される
- マウス操作への最適化
- ペイン、タブ、名前付きワークスペースを持つ
- 通信は Unix ドメインソケットのみ。TCP を開かず、外部へも接続しない

## インストール

```sh
cargo install koshi
```

## 使い方

```sh
koshi                 # 起動してアタッチする。サーバーが無ければ起動する
koshi kill            # サーバーを止める（状態を保存して終了）
koshi server          # 前面でサーバーを動かす
koshi server --daemon # 端末から切り離してサーバーを動かす
koshi --version
```

アタッチ中のクライアントを終了しても、サーバーとペインのプロセスは動き続ける。
もう一度 `koshi` を実行すると同じ画面に戻る。

ペインで動くシェルには `KOSHI_PANE` が入る。起動ファイルから自動でアタッチするときは、
これを見て二重起動を避ける。

```zsh
if [[ -o interactive && -z $KOSHI_PANE ]]; then
  exec koshi
fi
```

## 操作

### 状態

leader の直後の 1 キーをコマンドとして解釈する。`SCROLL` だけはキーを押しても留まる。

| 状態 | 入り方 | キー | 抜け方 |
| --- | --- | --- | --- |
| `NORMAL` | 起動直後、コマンドの実行後 | そのままペインへ送る | — |
| `PANE` / `TAB` / `SESSION` | `Ctrl+p` / `Ctrl+t` / `Ctrl+o` | 次に押した 1 キーだけを実行 | 実行後。`Esc`、同じ leader、割り当てのないキーでも戻る |
| `SCROLL` | `Ctrl+s` | 次に押した 1 キーを実行し、そのまま留まる | `Esc`、同じ leader、割り当てのないキー |
| ワークスペース一覧 | `Ctrl+o w` | 移動、切替、作成、改名、削除、設定 | `Enter` で切替、`q` か `Esc` で閉じる |

### leader を使わない操作

`Alt` + 矢印は leader を押さずに利用できる。

| キー | 動作 |
| --- | --- |
| `Alt`+`←` / `↑` / `↓` / `→` | その方向のペインへフォーカス。ペインが無いときは `←` / `→` が前 / 次のタブ（折り返し） |

### leader を使う操作

ステータスバーの左端が `[NORMAL]` / `[PANE]` / `[TAB]` / `[SESSION]` / `[SCROLL]`
になり、leader 待ちのあいだはそのグループで使えるキーのヒントが並ぶ。

| leader | グループ |
| --- | --- |
| `Ctrl+p` | ペイン |
| `Ctrl+t` | タブ |
| `Ctrl+o` | セッション |
| `Ctrl+s` | スクロール |

| グループ | キー | 動作 |
| --- | --- | --- |
| ペイン | `←` / `↑` / `↓` / `→` | 左 / 上 / 下 / 右のペインへフォーカス |
| ペイン | `p` | 次のペインへフォーカス |
| ペイン | `;` | 直前にフォーカスしていたペインへ戻る |
| ペイン | `n` / `r` | 右に分割 |
| ペイン | `d` | 下に分割 |
| ペイン | `x` | ペインを閉じる |
| ペイン | `z` | 全画面化の切り替え |
| ペイン | `f` | フローティングペインの表示切り替え |
| タブ | `n` | タブ作成 |
| タブ | `x` | タブを閉じる（最後の 1 枚は残る） |
| タブ | `r` | タブ名の変更 |
| タブ | `←` / `→` | 前のタブ、次のタブ |
| タブ | `1`〜`9` | その番号のタブへ |
| タブ | `Tab` | 直前に見ていたタブへ |
| セッション | `w` | ワークスペース管理画面 |
| セッション | `r` | 現在のワークスペース名の変更 |
| セッション | `d` | デタッチ |
| スクロール | `↑` / `↓` / `k` / `j` | 1 行上 / 下 |
| スクロール | `Ctrl+f` / `Ctrl+b` | 1 ページ下 / 上 |
| スクロール | `d` / `u` | 半ページ下 / 上 |
| スクロール | `Ctrl+c` | 末尾へ戻る |

フローティングペインはタブに 1 枚だけ出せる。表示中はキー入力がそのペインへ送られ、
`Ctrl+p` では `f`（隠す）、`x`（閉じる）、`d`（デタッチ）だけが効く。`Esc` でも隠れるが、
中のプログラムが alternate screen を使っているあいだは、そのプログラムへ渡る。

### マウス

クリックで入力先を選び、ホイールで履歴を読む。アプリがマウス報告を有効にしている
あいだは、ホイールと中・右ボタンをアプリへ送る。alternate screen ではホイールを
`↑` / `↓` に変えて送る。

左ボタンのドラッグは常に koshi 側の選択動作になり、離すと OSC 52 でクリップボードへ入る。
動かさずに離したクリックだけは、報告中のアプリへ press と release を送る。
コピーすると右下に `copied N chars` が 2 秒出る。

ペインの境目は左ボタンで掴んで動かせる。どちらのペインも 1 桁（1 行）を下回らない。
ワークスペース一覧の行もマウスで選べる。

### SSH ワークスペース

ワークスペース一覧で `c` を押すと設定画面が開く。`↑` / `↓` で項目を選び、`Enter` で編集、
`Esc` で一覧へ戻る。項目は SSH alias と記録の ON/OFF の 2 つで、記録は「ペイン出力の記録」に
書く。SSH alias には `~/.ssh/config` の `Host` に書いた名前を 1 つ入れる。空にすると通常の
ワークスペースに戻る。

alias を持つワークスペースでは、新しいペインを作るたびに `ssh <alias>` を 1 プロセス起動する。
koshi は接続を共有しないので、使い回したいときは OpenSSH 側で設定する。

```sshconfig
Host build
  HostName build.example.com
  ControlMaster auto
  ControlPath ~/.ssh/cm-%r@%h:%p
  ControlPersist 10m
```

- 設定を変えても既存のペインは切断しない。新しいペインから新しい設定を使う
- alias を確定すると `ssh -G <alias>` を 1 回実行し、成否だけを表示する。失敗しても保存する
- `ssh` が終わるとそのペインは閉じる。ワークスペースの定義は残る

### ペイン出力の記録

ワークスペース単位で、ペインに表示された文字をファイルに残す。既定は OFF。

ワークスペース一覧で `c` を押して設定画面を開き、`↓` で `record:` の行へ移って `Enter` で
ON/OFF を切り替える。切り替えた瞬間から、そのワークスペースで走っているペイン（フローティング
を含む）が記録を始め、OFF にするとその場で止まる。以降に作るペインも同じ設定に従う。
止めたときは未確定の行を書き出して閉じる。ファイルは残る。

保存先は既定で `$XDG_STATE_HOME/koshi/record`（無ければ `~/.local/state/koshi/record`）。
1 ペインにつき 2 つのファイルを作る。

```text
<root>/<YYYYMMDD>/<workspace-name>-<workspace-id>/<pane-id>-<HHMMSS>.log
<root>/<YYYYMMDD>/<workspace-name>-<workspace-id>/<pane-id>-<HHMMSS>.times
```

- `.log` は画面に出た文字だけで、色とカーソル制御は入らない。確定した行を 1 行ずつ書く
- `.times` は行ごとの時刻。ISO 8601 のローカル時刻を 1 行に 1 件書き、行番号が `.log` と対応する
- `vim` や `less` などが alternate screen に描いた内容は記録しない
- ディレクトリは 0700、ファイルは 0600
- ワークスペース名を変えると、未圧縮の記録ディレクトリも新しい名前に移る

### 週次アーカイブ

終了した暦週（月曜〜日曜）の記録を、サーバー稼働中に 1 週間に 1 回まとめる。進行中の週は
触らない。起動時と 7 日ごとに走り、直近 8 週のうちまだまとめていない週を処理する。

```text
<root>/<YYYYMM>/<開始日>-<終了日>.tar.gz
```

- 月のディレクトリは週開始日の属する月。メンバーは `<YYYYMMDD>/<workspace-name>-<id>/<...>.log|.times`
- まとめた元のファイルは削除する。処理中に書き込みがあったファイルは削除せず、次回に回す
- 圧縮は週 1 回 `tar` を外部プロセスで 1 回呼ぶだけで、crate は増やさない
- `record_retain_days` が 0 なら無期限。値があるときは週開始日から数えて期限切れの
  `.tar.gz` を同じ処理で削除する

### 記録の閲覧

```sh
koshi record show                      # ワークスペース一覧 → 日付一覧 → ログ
koshi record show <workspace>          # 日付一覧から
koshi record show <workspace> <date>   # ログを直接
```

- `<workspace>` は名前でも ID でもよい（ID を優先）。`<date>` は `YYYY-MM-DD` か `YYYYMMDD`
- 日付一覧には記録がある日だけを、未圧縮と週次アーカイブの両方から並べる
- 表示は読み取り専用。`Tab` で全ペインを時刻順に混ぜる Chronological と、ペインごとの
  Per-pane を切り替える。`↑`/`↓` と `PageUp`/`PageDown` で動かし、`Esc` で戻り、`q` で終了する
- 各行は時刻とペイン ID を添えて、記録した本文をそのまま出す
- 起動中のペインの未確定行は、閲覧時にサーバーの画面から補って `p<id>+` として末尾に出す。
  ファイルには書かない
- `.log` と `.times` の行数がずれているときは短いほうまで表示し、警告を 1 行出す

## 設定

`$XDG_CONFIG_HOME/koshi/config.toml`（無ければ `~/.config/koshi/config.toml`）。
ファイルが無ければ既定値で起動し、壊れていれば既定値で起動してその旨を標準エラーへ出す。

```toml
leader = "C"        # "C" は Ctrl+p/t/o/s、"A" は Alt+p/t/o/s
scroll_lines = 3    # ホイール 1 ノッチの行数
history_lines = 10000
# record_root = "/srv/koshi/record"  # 記録の保存先。既定は状態ディレクトリの record
# record_retain_days = 0             # 週次アーカイブの保持日数。週開始日から数える。0 は無期限
```

## 状態ファイル

- 置き場所は `$XDG_STATE_HOME/koshi/state.bin`（無ければ `~/.local/state/koshi/state.bin`）。
  `KOSHI_STATE_DIR` か `KOSHI_RUNTIME_DIR` を指定すると、そのディレクトリに置く
- ディレクトリは 0700、ファイルは 0600。3 秒ごと（変更があったときだけ）と終了時に、
  一時ファイルからの `rename` で置き換える
- 残るのはワークスペースとタブの並び、レイアウト、フォーカス、ペインの作業ディレクトリ、
  履歴のテキスト、ワークスペースの ID と SSH alias、記録の ON/OFF。履歴は 1 ペイン 2000 行、
  全体で 400 KB まで
- 復元すると各ペインは同じディレクトリで新しいシェルを開く。実行中だったプロセスは戻らない。
  SSH ペインも接続は再開せず、ローカルのシェルになる。フローティングペインは保存しない
- 形式バージョンは 2。形式 1 のファイルは読み替えて移行する。ID は並び順で 1 から振り、
  SSH alias は空で始まる
- 壊れている、形式が違う、チェックサムが合わないときは空の状態で起動し、最初のクライアントへ
  1 行知らせる。読めない SSH alias は捨てて、その旨を 1 行知らせたうえでワークスペースは残す

## コピー

コピーは OSC 52 を使う。端末が受け付ける上限は端末ごとに違い、koshi からは
分からないので、切り詰めも分割もしない。

`git log` の既定の pager（`less -FRX`）は alternate screen を使わない。この場合は
ホイールが koshi の履歴を動かすので、ログ全体を読みたいときは `LESS=` を空にするか
`core.pager = less -R` を設定する。
